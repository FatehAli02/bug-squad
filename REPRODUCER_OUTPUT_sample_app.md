AssertionError: Expense dated 2024-05-31 (last day of May) was not found in

  where False = any(<generator ...>)

AssertionError: Monthly total for May 2024 should be 45.00 but got 30.00 —

**Summary:** `month_date_range` in `utils.py` computed the upper bound as

day of any month. All four tests prove this across 31-day months (May), 30-day
months (April), and leap-year February (Feb 29, 2024). The fix is to remove
the `- 1` so the end is `date(year, month, last_day)`.

## Bug 03 — `over_budget_categories` misses $0.01-over-limit spending

**File:** `sample_app/tests/test_bugs.py`
**Class:** `TestBug03OverBudgetBoundary`
**Tests:**
- `test_exactly_at_limit_is_not_over_budget` *(PASSES — boundary correct)*
- `test_one_cent_over_limit_is_over_budget` **(FAILS — bug still present)**

**Status:** ❌ FAILING

**Failure output:**
```
AssertionError: Spending one cent over the limit must be flagged as over budget
assert 'food' in []
```

**Summary:** `over_budget_categories` (api.py line 221) filters by
`s["percent_used"] > 100`. When spending is $100.01 against a $100 limit,
`round(100.01 / 100 * 100, 1)` evaluates to `100.0` due to Python's
floating-point rounding, so `100.0 > 100` is `False` and the category is
silently excluded from the over-budget list even though spending has exceeded
the limit. The fix is to filter on the pre-computed `s["over_budget"]` flag
(`remaining < 0`) instead of re-deriving from `percent_used`.

## Bug 04 — Mutable default argument in `to_csv_rows`

**File:** `sample_app/tests/test_bugs.py`
**Class:** `TestBug04MutableDefaultHeaders`
**Test:** `test_mutable_default_can_be_corrupted_externally` **(FAILS — bug still present)**

```
AssertionError: Default header was corrupted by external mutation: 'id,title'
  (expected 'id,title,amount,category,date,notes')
  assert 'id,title' == 'id,title,amount,category,date,notes'
```

**Summary:** `to_csv_rows` in `utils.py` is declared with
`headers: List[str] = []`. Python evaluates default argument expressions once
at function-definition time, so all calls that omit `headers` share the same
list object. The test retrieves that shared default via `inspect.signature`,
appends values to it, then calls `to_csv_rows` without passing `headers`.
Because the default is now truthy and mutated to `["id", "title"]`, the wrong
header row is produced. The fix is `headers: Optional[List[str]] = None`.

**Status:** ❌ FAILING

**Failure output:**
```
AssertionError: _today_utc() still uses UTC time instead of the local clock.
  Function source:
  def _today_utc() -> str:
      """Return today's date as an ISO-8601 string, based on UTC time."""
      return datetime.now(tz=timezone.utc).strftime("%Y-%m-%d")
```

**Summary:** `main._today_utc()` calls `datetime.now(tz=timezone.utc)`, which
returns the current UTC timestamp. For users in UTC+ timezones, the UTC date
lags their local date — e.g., at 01:00 local time in UTC+3, UTC is still the
previous calendar day. The test inspects the function's source code and asserts
the UTC sentinel is absent; the assertion fails because the sentinel is present.
The fix is to use `date.today().isoformat()`.
