## 1. Root Cause Summary
ExpenseTracker.over_budget_categories (api.py line 221) filters by s["percent_used"] > 100, but percent_used is computed as round(spent / monthly_limit * 100, 1) in budget_status (utils.py line 126). Python's banker's rounding causes round(100.1, 1) to evaluate to 100.0, so 100.0 > 100 is False and a category spending $100.01 against a $100.00 limit is silently excluded from the over-budget list. Meanwhile budget_status already computes the exact boolean over_budget: remaining < 0 (no rounding), which is True for $100.01 spent. The fix is to filter by s["over_budget"] directly instead of re-deriving from the rounded percent_used.
